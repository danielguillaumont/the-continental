# v0.1.0 release candidate — My Evidence

**Status:** Release preparation; do not create the `v0.1.0` tag until CI and the final checklist pass.

## What this milestone actually delivers

The Continental now stores a professional profile, employment experience, projects, proof records, evidence-derived skills, and certification records in a relational model. The main UI allows the owner to add, inspect, update, and remove supported records. Project-to-evidence, experience-to-project/evidence, and certification-to-skill/evidence relationships are reusable: linking does not duplicate or transfer the original record.

The release remains useful without calling a model API. That is the point of this version: dependable career facts first, automated reasoning later.

## Known constraints / deliberately deferred

- **Local-only, unauthenticated single-user development build.** Never expose the API, web instance with private records, or PostgreSQL publicly. There is no account isolation, authorization, or hosted-demo environment. The Compose configuration now binds PostgreSQL to loopback rather than all network interfaces; validate this after applying the release-preparation patch.
- Verification labels are owner-entered; they are not issuer or independent third-party validation.
- Skills are derived from evidence relationships; no skill proficiency prediction or automatic resume inference is claimed.
- No AI matching, job parsing, embeddings, applications, agents, or generated resumes in v0.1.
- No production hosting, telemetry pipeline, or automated browser E2E/screenshot regression suite in this release.
