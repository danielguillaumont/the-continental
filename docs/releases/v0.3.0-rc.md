# v0.3.0 — Evidence Match | Release candidate

**Status:** Code and documentation candidate; **not yet tagged or published**. The latest published release is v0.2.0. Do not create the `v0.3.0` tag until all gates below pass.

## Release summary

The Continental now connects saved job requirements to candidate career evidence using existing Skill tags. Within a Dossier, each requirement is inspectable: saved evidence records, literal Skill tags, linked projects and experiences, and explicit unmatched states. Owner-reviewed supporting/not-relevant decisions are separate from automated candidate discovery and persist with reasoning, an original-input fingerprint, and stale-review visibility.

The original job posting and v0.2 AI-extraction consent/approval boundaries remain intact. No score, hiring prediction, independent credential check or automatic decision is produced.

## Implemented scope

- Deterministic, read-only `/evidence-match-preview` endpoint using literal Skill tags, bounded candidates and explicit unmatched cases
- Three opt-in, explicitly fictional demo Dossiers and linked project/evidence examples; demo seeding defaults to dry-run and requires an existing-data backup before writes
- Responsive Evidence Match navigator with read-only drill-down into original Evidence and linked work
- Human review API for `supports` / `not_relevant` decisions with notes, reviewed-source fingerprints, stale detection, safe reversal and removal
- Reversible review UI with bounded candidate selection, saved-review reconciliation after uncertain writes and no automatic retry of ambiguous PUT/DELETE
- Automated fictional screenshot capture with UI-readiness checks, bounded read-only error recovery, local browser diagnostics and public-sharing guard
- New UI/package release labels and recruiter-first README gallery, backed by manually checked fictional screenshots

## Explicit limitations

- Local-only, single-user and unauthenticated. Do not expose API or PostgreSQL publicly with career records. No tenant isolation or production-ready authentication.
- Matching is **literal Skill-tag linkage**, not semantic retrieval, skill proficiency, suitability scoring or job selection.
- Candidate Evidence is not automatically confirmed; saved owner reviews are not independent employer validation. A record's owner-entered “verified” status is not third-party verification.
- Live OpenAI extraction is not verified. Provider is disabled unless explicitly configured and each use consented to; offline tests use a simulated provider.
- No automatic application generation, public hosting, job board scraping, resume authorship or multi-user features are included in v0.3.
- Privacy and production hardening remain future work. The fictional screenshot fixture should never overwrite or masquerade as a real professional record.

## Proposed GitHub release description (after gates pass)

**The Continental v0.3.0 — Evidence Match** connects saved job requirements to inspectable candidate career evidence. Explore each requirement, inspect exact Skill-to-Evidence links and related projects, and explicitly review whether a candidate supports the requirement. Saved decisions can be edited, removed and marked stale when underlying records change. The app retains the original posting and keeps AI suggestions separate from owner control. This is a local-development milestone without verified live AI extraction, public authentication, qualification scoring or independent credential verification.
